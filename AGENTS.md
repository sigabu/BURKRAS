# БУРКРАС / BURKRAS — правила и контекст проекта

## Задача и статус

Создать продающий демонстрационный сайт начинающей компании в Красноярске. Четыре направления: алмазное бурение, алмазная резка, усиление проёмов, демонтаж. Пользователь разрешил создать публичный репозиторий `sigabu/BURKRAS` и опубликовать сайт в GitHub Pages. Рабочее название и айдентика разработаны в проекте; юридическая проверка названия не проводилась.

Текущий этап: статический демонстрационный сайт. Формы проверяют ввод и показывают честное демо-подтверждение. Они не передают и не сохраняют персональные данные. Реальные контакты, прайс, реквизиты, фотографии объектов и юридические тексты пока не предоставлены владельцем.

## Обязательные правила контента

- География — город Красноярск, все семь районов. Не обещать работу по всему краю.
- Не выдумывать возраст компании, число объектов, клиентов, сотрудников, рейтинги, отзывы, допуски, страховку, бренды оборудования, гарантированные сроки ответа или выезда.
- Не публиковать чужие номера телефонов, адреса, фотографии, отзывы или логотипы.
- Усиление и вмешательство в несущие конструкции описывать как работу по проекту с предварительной оценкой. Не давать универсальных инженерных решений.
- Демо-цены калькулятора не являются утверждённым прайсом. Обозначать их непосредственно рядом с результатом.
- Подтверждение формы в демо не должно утверждать, что компания получила заявку или перезвонит.
- Не добавлять аналитику или хранение контактов без отдельной задачи.

## Архитектура

Статические HTML/CSS/ES-модули, без клиентского фреймворка и без сборки. Сайт работает в подпапке `/BURKRAS/`; все внутренние пути относительные. Для разработки — Node.js, встроенный HTTP-сервер. Зависимости в браузере отсутствуют. GitHub Pages публикует только каталог `site/` через GitHub Actions, документация и тесты остаются в репозитории.

- `site/index.html` — страница, семантические секции, диалоги, формы.
- `site/assets/styles.css` — токены, компоненты, адаптивность.
- `site/assets/app.js` — калькулятор, меню, диалоги, формы.
- `site/assets/config.js` — DEMO_MODE, API_URL, контакты и демонстрационные тарифы.
- `site/assets/pricing.js` — чистый расчёт ориентировочного диапазона.
- `site/assets/leads.js` — валидация и адаптер заявки, единственная точка подключения API.
- `site/assets/*.svg` — собственная векторная айдентика и схемы.
- `docs/backend.md` — будущий API, БД, файлы, уведомления, условия запуска.
- `.github/workflows/pages.yml` — проверка и публикация `site/`.

Пометки `TODO(BACKEND)`, `TODO(CONTACTS)`, `TODO(PRICING)` должны оставаться в соответствующих точках кода. Не хранить серверные секреты в браузере или Git. DEMO_MODE нельзя выключать до готовности сервера и утверждения реальных контактов и условий обработки данных.

## Команды и проверка

- `npm run dev` — http://127.0.0.1:4173/BURKRAS/
- `npm test` — значимые проверки расчёта, валидации, демо и серверного адаптера.
- `npm run check` — синтаксис и проверка ссылок/ресурсов статического сайта.
- Проверять браузером desktop и mobile: отсутствие горизонтального скролла и ошибок, меню, формы, валидация, смена услуги/параметров калькулятора, FAQ, закрытие диалогов и клавиатурный фокус.
- Скриншоты и временные файлы хранить в игнорируемых `output/playwright/` и `tmp/`.
- Перед публикацией запускать все проверки; после — проверять URL Pages и результат workflow.

## Дальнейшие изменения

Сохранять честность демонстрации и собственную айдентику. Заменять примеры только данными владельца. Реальное портфолио добавлять после получения фотографий и разрешения на публикацию. При подключении сервера следовать `docs/backend.md`, обновить политику, проверить серверную валидацию и ошибки. Не подключать БД напрямую из браузера.
